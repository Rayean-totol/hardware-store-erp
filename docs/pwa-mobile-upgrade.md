# Mobile, desktop and PWA upgrade

Branch: `claude/pwa-mobile-upgrade`. Built on `claude/phase-4b-purchase-orders`.
Out of scope and not touched: Phase 4C, Phase 4D, APK packaging, database migrations and functions,
Row Level Security, production deployment and hosting configuration.

## 1. Owner decisions and how they were applied

| # | Decision | Applied as |
|---|---|---|
| 1 | No offline transaction queues or automatic synchronisation | The app no longer creates or sends queued work. The sync engine is no longer started, no interval flushes, and the `online` event does not replay anything. Every stock, sale, supplier and purchase write is a direct call to the server. |
| 2 | Disable all business writes while offline | A write gate (`lib/connection-gate.ts`) is closed unless the server was reached recently. Every repository write method is wrapped (`lib/write-guard.ts`), so a call made while the gate is closed is refused with `offline.writes_disabled` and nothing is sent. Save and submit buttons are also disabled, with a short explanation. |
| 3 | Cache only safe static assets | The service worker caches hashed `_next/static` bundles, icons, the manifest and the offline page. It never handles other origins (Supabase), requests with `Authorization`, non-GET requests or page navigations (those go to the network, with the offline page as fallback). Rules are in `public/sw-rules.js` and are unit-tested. |
| 4 | Clear sensitive local data on sign-out, but never discard pending changes silently | Sign-out checks for unsent items (legacy outbox entries and held POS sales). If any exist, a dialog lists them and requires "Delete and sign out". Cancel keeps everything. Without pending items, sign-out clears local data directly. If the server sign-out fails (offline), the session is removed locally. |
| 5 | Mobile bottom navigation and Android back button | Bottom bar: Dashboard, Products, Inventory, POS / Sales, More, filtered by permission. More opens a sheet with every module, install, language and sign-out. Android back closes the sheet or dialog first (`lib/use-back-layer.ts`). |
| 6 | Online / Offline / Reconnecting indicators | Header indicator from a state machine (`lib/connection.ts`) fed by browser events and a health check against the Supabase auth health endpoint every 30 s while visible. Tapping it checks again. An amber banner appears while not online. |
| 7 | Responsive POS, barcode input and all remaining pages | POS: total and "Review & pay" bar on phones, scanner field kept focused after each item, checkout revalidates the server first and is idempotent. Responsive overflow matrix passes for 15 pages at 320–1440 px (section 3). |
| 8 | Manifest, icons, service worker and install support | Manifest with relative `start_url`/`scope` for the `/hardware-store-erp/` subpath; 192, 512, maskable 512 and 180 px Apple icons generated by `scripts/generate-icons.py`; service worker registered in production only; waiting update prompt; Android/desktop install button; iOS instructions. |
| 9 | Run all tests and fix failures | See section 4. |
| 10 | Preserve Supabase data, authentication, permissions and ERP behaviour | No migration, RPC, RLS policy or table was changed (`git status supabase` is empty). Database (267) and API (21) test suites pass. Permission checks on the client are unchanged. |

## 2. What changed, by area

- **Connection and writes:** `lib/connection.ts`, `lib/connection-gate.ts`, `lib/write-guard.ts`,
  `lib/services-guard.ts`, `providers/connection-provider.tsx`, `components/connection-indicator.tsx`,
  `components/write-hint.tsx`.
- **Inventory:** the movement form and stock overview read and write through the server repository
  (`listStockLevels`, `searchProducts`, `applyMovements`). Each submission gets one idempotency key;
  a retry of the same entry reuses it (a timestamp in the key was found and fixed by a test). The
  overview no longer shows queued counts. Movement history needs a connection.
- **Legacy data:** `lib/local-data.ts` and `features/inventory/legacy-pending-panel.tsx`. The old
  IndexedDB outbox is read only to list anything it never sent. Those items are not counted in
  stock. They can be deleted one by one after confirmation. When nothing is pending, the old offline
  database is deleted on load.
- **Shell and navigation:** `components/app-shell.tsx`, `lib/navigation.ts`, `lib/use-back-layer.ts`.
- **POS:** `features/pos/pos-screen.tsx` (connection state, revalidation, scanner focus, mobile bar).
- **PWA:** `public/manifest.webmanifest`, `public/sw.js`, `public/sw-rules.js`, `public/offline.html`,
  `public/icons/*`, `components/pwa-register.tsx`, `components/pwa-install.tsx`,
  `scripts/stamp-sw.mjs` (gives each build its own cache name), `app/layout.tsx` metadata.
- **Removed from the UI:** `providers/sync-provider.tsx`, `features/inventory/sync-panel.tsx`,
  `lib/offline-store.ts`. The `packages/data/src/offline` package is still present but nothing in the
  app imports it. Recommended follow-up: delete it in a separate change after review.
- **Translations:** 27 new keys in English, Arabic and Bangla (`packages/i18n`).

Browser scenarios (Chromium, mocked Supabase responses with fake fixture data):

2. Phone: a storekeeper (no sales permission) has no POS tab.
3. Desktop: sidebar shown, bottom bar hidden, collapse works.
4. Connection indicator reports Online after the server check.
5. Offline: product search refused, nothing sent to the server.
6. Offline: product form and supplier form Save buttons disabled.
7. Online: a receipt is sent once, with a client key, after the product is found.
8. Phone POS: scan adds a line, review bar appears, checkout disabled offline.
9. PWA: service worker registers in production; manifest and all icons are served.
10. PWA: offline navigation shows the offline page; only static assets are cached.
11. PWA update: a second worker waits, the prompt appears, and the page reloads only after "Update now".
12. iPhone: the More sheet explains "Add to Home Screen".
13. Legacy data: unsent items are listed; sign-out asks first; Cancel keeps them.
14. Legacy data: when nothing is unsent, the old offline database is removed on load.
15. Arabic on a phone at 320 px: right-to-left, translated tabs, no horizontal scroll.
16. Layout: 15 authenticated pages (dashboard, products and new product, inventory and move/history,
    POS, suppliers and new supplier, warehouses, purchase orders and new order, team, catalog, labels)
    at 320, 390, 430, 600, 768, 1024 and 1440 px: no horizontal scroll (105 page loads).

Defects found by these tests and fixed in this branch:
- Dashboard, catalog and other card grids had no mobile column count and overflowed at 320 px.
- The bottom bar's columns were wider than the screen at 320 px (long Arabic labels).
- Movement retries generated a new idempotency key each time (the key was tied to a timestamp).
  Fixed so one submission keeps its key and time.
- The navigation link inside the More sheet was undone by the back-button step. Fixed.
- The POS showed a second connection indicator. Removed.
- Sign-out dialog's close button and Cancel button had the same label. Fixed.

## 4. Not tested, and known limits

- **Real devices:** real Android Chrome, real iOS Safari and an installed app were not tested. The
  harness runs desktop Chromium with a phone viewport and user agent.
- **Install prompt:** the browser's `beforeinstallprompt` event is not produced in headless
  Chromium, so the Android/desktop install button is not exercised. The iOS text is tested.
- **Update prompt:** tested by swapping in a second worker version in the served copy, not by a
  real second deployment.
- **Real Supabase:** not contacted. Row Level Security and server behaviour are unchanged, but the
  new flows (revalidation, refusal when offline) were not tested against the live project.
- **Camera barcode scanning:** not built. Scanner hardware (USB or Bluetooth keyboard) and typed
  codes work, because they arrive as text in the search field.
- **Offline navigation:** a page the user has never opened while online cannot be opened offline,
  because its code is not cached yet. Once the code is cached, moving between pages inside the app
  works offline. A full reload while offline shows the offline page, because page HTML is not
  cached on purpose (it must not be served stale). Precaching every route would make the cache much
  larger; this was not done.
- **Performance:** no measurements were taken (no Lighthouse run) and no loading skeletons were
  added. Routes are already split by Next.js.
- **Visual review:** checks were automated (overflow, roles, text). Screens were not reviewed by eye.
- **Pending legacy entries:** the app does not send them. A user with pending items must delete them
  or re-enter the movement manually.

## 5. Running the checks

```bash
export NEXT_PUBLIC_BASE_PATH=/hardware-store-erp
export NEXT_PUBLIC_SUPABASE_URL=https://example.supabase.co
export NEXT_PUBLIC_SUPABASE_ANON_KEY=placeholder
pnpm --filter @erp/web build

# Serve a copy of the build under a scratch folder, then run the browser suite.
SCRATCH=<a scratch folder>
rm -rf "$SCRATCH/hardware-store-erp" && cp -r apps/web/out "$SCRATCH/hardware-store-erp"
(cd "$SCRATCH" && python3 -m http.server 4173) &
E2E_SITE="$SCRATCH" node tests/e2e/run.cjs
```

The update scenario temporarily rewrites `sw.js` in the scratch copy and restores it afterwards.
Set `E2E_SITE` to the scratch folder, never to the repository.
